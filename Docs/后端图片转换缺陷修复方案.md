### Defect 2.1（根因）: `get_pillow_format` 结构性失效

**文件：** `app/utils/PictureUtils.py:330-332`

**修改：** 同时兼容带点和不带点的输入：

```python
def get_pillow_format(ext: str) -> Optional[str]:
    """扩展名（带点或不带点均可） → Pillow 格式名。"""
    ext_lower = ext.lower()
    if ext_lower in EXT_TO_FORMAT:
        return EXT_TO_FORMAT[ext_lower]
    # 不带点（如前端 output_formats 传值）→ 补点后查找
    return EXT_TO_FORMAT.get(f".{ext_lower}")
```

### Defect 2: `output_formats` 重复 + 11: `OUTPUT_EXTENSIONS` 语义混用

**文件：** `app/utils/PictureUtils.py:59-61`

**修改：** 新增按格式名去重的常量，替代原有的扩展名列表：

```python
# 删除或注释掉：

OUTPUT_FORMAT_NAMES: List[str] = sorted(
    set(v.lower() for v in OUTPUT_FORMATS.values())
```

**文件：** `app/services/PictureService.py:107`

**修改：** 改用新常量：

```python
# 改前：
```

```python
from app.utils.PictureUtils import (
```

### Defect 10（连锁）: `no_alpha_formats` 不覆盖非规范名

**文件：** `app/utils/PictureUtils.py:280-322`

修复 Defect 2.1 后，`get_pillow_format` 始终返回规范名（如 `"JPEG"`），此问题自然消除。无需额外修改 `resolve_color_mode`。

如需防御性加固，可在 `resolve_color_mode` 入口处规范化一次：

```python
def resolve_color_mode(img_mode, target_format, requested_mode, has_transparency):
    # 规范化格式名（防御上游可能传非规范名）
    canonical = get_pillow_format(target_format)
    if canonical:
        target_format = canonical
    # ... 后续逻辑不变
```

### Defect 3: AVIF 编码忽略 quality

**文件：** `app/services/PictureService.py:357-358, 482-504`

**方案 A（推荐）：** 切到 Pillow 12.3 原生 AVIF save，删除 pyavif 编码路径。

项目已安装 Pillow 12.3，原生支持 AVIF 读写，`get_save_kwargs` 中 AVIF 的 quality 处理已是完整逻辑，只是从未被调用（因为走 pyavif 分支跳过了）。切过来即可生效：

修改 `_convert_one_sync:357` 中 AVIF 分支：

```python
# 改前：
if target_pillow_fmt == "AVIF":
    converted_data = self._encode_avif(img)

# 改后：
if target_pillow_fmt == "AVIF":
    save_kwargs = get_save_kwargs(
        params.target_format, params.quality, params.lossless
    )
    buf = io.BytesIO()
    img.save(buf, format="AVIF", **save_kwargs)
    converted_data = buf.getvalue()
```

删除 `_encode_avif` 方法（`_open_avif` 保留，pyavif 仍用于解码）。

**方案 B（备选）：** 若 Pillow 12.3 AVIF 写入不满足需求，仍走 pyavif 但传入 quality。

修改 `_encode_avif` 签名：

```python
def _encode_avif(self, img: Image.Image, quality: Optional[int] = None) -> bytes:
```

调用处改为 `self._encode_avif(img, params.quality)`。但 `pyavif.Encoder` 的 quality API 未经核实（文档编写时未查阅 pyavif 对应版本），可能不支持直接设置 quality，此时 `if quality is not None: encoder.quality = quality` 会静默忽略。建议优先方案 A。

## 中等问题

### Defect 4: heif 详情返回但不可输出

**文件：** `app/services/PictureService.py:100-109`

> 注：原 Defect 5（SVG 不可输出）已确认是后端实现错误——SVG 应为输出格式。`OUTPUT_FORMATS` 的 `v not in ("HEIF", "SVG")` 已修正为 `v != "HEIF"`。SVG 输出通过 `_save_as_svg` 方法实现（见新增修复 4.1）。

**方案：** `get_supported_formats` 只返回当前输出格式的详情，过滤掉仅输入格式（现仅 heif）：

```python
async def get_supported_formats(self) -> Dict[str, Any]:
    # 只返回 output_format 中包含的格式的详情
    details = {
        key: FORMAT_DETAILS[key].to_dict()
        for key in OUTPUT_FORMAT_NAMES
        if key in FORMAT_DETAILS
    }
    return {
        "input_formats": [ext.lstrip(".") for ext in INPUT_EXTENSIONS],
        "output_formats": OUTPUT_FORMAT_NAMES,
        "format_details": details,
    }
```

> 或保留全量（不影响功能），视数据整洁性需求决定。

### Defect 6: `convert` 方法是同步死代码

**文件：** `app/services/PictureService.py:115-176`

**方案：** 删除 `convert` 方法。当前无调用方，`convert_stream` 是唯一的实际入口。

如需保留作为备选，标注 `@deprecated` 并在方法内加 `assert False, "Use convert_stream instead"`。

> `convert` 和 `convert_stream` 都调用 `_convert_one_sync` 并传入相同的 `params` 参数。Defect 3（AVIF quality）的修改在 `_convert_one_sync` 内部（从 `params.quality` 取值），两个调用方都会自动继承该修复。不存在先后依赖——修哪个都不影响另一个。

## 轻微问题

### Defect 8: JPEG quality `ge=0` 矛盾

**文件：** `app/controllers/PictureController.py:62`

**修改：**

```python
# 改前：
quality: Optional[int] = Form(None, ge=0, le=100, ...),

# 改后：

```

`get_save_kwargs` 中 WebP/AVIF 的 `max(0, min(100, quality))` 钳位不变，各自处理其合法范围。

### Defect 9: BMP `supports_transparency` 标记保守

**文件：** `app/utils/PictureUtils.py:131`

**方案：** 可选修改。如需改为 `True`：

```python
# 改前：
"bmp": FormatDetail([".bmp"], "image/bmp", False, False, False, None),

# 改后：
"bmp": FormatDetail([".bmp"], "image/bmp", True, False, False, None),
```

> 需确认：32 位 BMP 的 alpha 在各下游场景中兼容性无问题。保持 `False` 是安全选项。

### Defect 12: SVG 渲染无尺寸限制

**文件：** `app/services/PictureService.py:440`

**修改：** 仅限制宽度，让 cairosvg 按 viewBox 比例自动计算高度，保持宽高比不变：

```python
# 改前：
png_data = cairosvg.svg2png(bytestring=data)

# 改后：
png_data = cairosvg.svg2png(
    bytestring=data,
    output_width=4096,  # 仅限制宽度，高度等比缩放
)
```

> 不可同时设 `output_width` + `output_height`——cairosvg 会强制输出精确尺寸，忽略 SVG 原始 viewBox 比例（1920×1080 横幅会被压成正方形，64×64 图标会被撑大浪费内存）。如需对两个维度都设上限，应在渲染后检查实际尺寸，超出时才 resize。

---

### Defect 13: `zip_url` 后端生成前端不用

**文件：** `app/services/PictureService.py:229-235`、`app/schemas/PictureSchema.py:54`

**方案 A（推荐——后端删除）：** 删除 `zip_url` 字段和生成逻辑：

- `PictureService.py` 删除 `zip_url = ...` 赋值及 `zip_url` 变量
- `PictureSchema.py` 删除 `zip_url: Optional[str] = None`
- 前端无需改动（本来就不用它）

**方案 B（前端跟进）：** 保留后端字段，修改前端 `handleDownloadBatch` 改用 `response.data.zip_url`。增加前后端耦合但不减少无用功。
