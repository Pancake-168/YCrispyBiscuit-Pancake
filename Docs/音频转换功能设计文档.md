# 音频转换功能设计文档

---

## 一、功能概述

"音频转换"（Audio Switch）是 Pancake 工具箱的音频处理模块。核心能力：

- 7 种主流音频格式互转
- 有损输出统一高质量 VBR 转码，无损输出直通（编码参数见 2.5）
- 展示时长、采样率等音频元数据
- 单文件与批量处理

对比图片转换：没有质量滑块、缩放裁切、色彩模式、透明通道、魔数检测。用户只选目标格式，点转换。

底层走 ffmpeg + ffprobe，二进制随 PyInstaller 打包进 exe。

## 二、格式覆盖

### 2.1 格式列表

| 格式       | 扩展名       | 有损 | MIME       | 选择理由                                         |
| ---------- | ------------ | ---- | ---------- | ------------------------------------------------ |
| WAV        | .wav         | 否   | audio/wav  | 无损无压缩，兼容性最广                           |
| FLAC       | .flac        | 否   | audio/flac | 无损压缩，开源，音乐存档标准                     |
| AIFF       | .aiff / .aif | 否   | audio/aiff | Mac 平台的 WAV 等价物，专业音频常用              |
| MP3        | .mp3         | 是   | audio/mpeg | 全球兼容性最好                                   |
| AAC        | .m4a / .aac  | 是   | audio/mp4  | Apple 生态标准，YouTube 音频流，使用量仅次于 MP3 |
| OGG Vorbis | .ogg         | 是   | audio/ogg  | 开源有损，同码率音质优于 MP3                     |
| OPUS       | .opus        | 是   | audio/opus | 低码率高质量，语音/流媒体首选，IETF 标准         |

7 种格式全部双向互转。

### 2.2 未列入的格式

| 格式       | 不列入的理由                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| WMA        | 微软私有格式，ffmpeg 解码受限，编码支持不稳定。存量用户极少，不值得为边缘格式增加维护成本                   |
| ALAC       | Apple 无损。可被 WAV/FLAC/AIFF 三种无损覆盖，转出去用户也能用。多一种无损格式只是增加选项数，不增加实用价值 |
| DSD / SACD | 发烧友领域，文件巨大、硬件绑定，不属于"日常工具箱"范围                                                      |

### 2.3 容器与编码器关系

用户容易混淆 OGG/OPUS 和 AAC/M4A。以下说明放在前端格式选择器旁边：

- `.ogg` = OGG 容器 + Vorbis 编码 → 格式标识 `ogg`
- `.opus` = OGG 容器 + Opus 编码 → 格式标识 `opus`
- `.m4a` = MP4 容器 + AAC 编码 → 格式标识 `aac`
- `.aac` = 裸 AAC 流（无容器） → 极少见，也支持

选择格式时用户选的是**编码方式**（Vorbis 还是 Opus、AAC 用什么容器），扩展名由后端统一处理，前端不暴露这个细节。

### 2.4 格式特有限制

- **有损→无损**：不会丢失更多质量，但也不会恢复已丢失的信息。MP3→FLAC 只是换容器，音质等同于原 MP3。后端在转换结果中通过 `warning` 字段提示用户（见 3.2）
- **无损→有损**：WAV/FLAC/AIFF→有损格式会有首次有损编码，码率由 2.5 的编码参数策略决定，不是“ffmpeg 默认质量”
- **元数据**：ffmpeg 自动保留可映射字段（标题/作者/专辑），不兼容字段静默丢弃。丢弃行为无法精确检测，不设 warning
- **WAV 4GB 上限**：单文件上限 200MB，远低于 4GB，此限制在本模块内不会触发，无需 RF64 处理
- **OPUS 采样率**：libopus 仅支持 8/12/16/24/48kHz，44.1kHz 输入会被 ffmpeg 自动重采样为 48kHz，结果中的 `sample_rate` 可能与源不同

### 2.5 有损输出编码参数策略（设计约定）

不做质量滑块，统一采用各编码器的高质量 VBR 档位：

| 目标格式 | 编码器与参数                                          | 说明 |
| -------- | ----------------------------------------------------- | ---- |
| WAV/AIFF | 无参数（PCM 直写）                                     | 无损 |
| FLAC     | 无参数（默认无损压缩）                                 | 无损 |
| MP3      | `-c:a libmp3lame -q:a 0`                              | LAME VBR 最高档 V0（约 245 kbps） |
| OGG      | `-c:a libvorbis -q:a 6`                               | 约 192 kbps 高质量档 |
| AAC      | 原生 aac 编码器高质量 VBR 档（具体 `-q:a` 数值实现阶段按 ffmpeg 构建实测后固化） | — |
| OPUS     | libopus 默认 VBR（不额外指定，实现阶段实测默认码率后固化） | — |

采样率保持源不变（OPUS 除外，见 2.4）。实现时把上表固化为 `AUDIO_ENCODE_ARGS` 常量（对齐图片版 `get_save_kwargs` 的“格式特定参数工厂”思路）。

```json
    }
```


与图片转换 ConvertResultItem 对比：移除 `original_resolution` / `converted_resolution`，新增 `duration_seconds` / `sample_rate`；保留图片版已有的 `warning` 通道（`Optional[str] = None`，成功时可携带用户可见提示，前端结果行展示）。

`warning` 的触发规则（对齐图片版"多帧仅保留首帧"提示的通道用法）：

- 源为有损格式（mp3/aac/ogg/opus）且目标为无损格式（wav/flac/aiff）时，`warning = "源文件为有损格式，转换为无损格式不会恢复已损失的音质"`；
- 其余场景为 `null`。

判定依据 `LOSSY_FORMAT_IDS` / `LOSSLESS_FORMAT_IDS` 常量（与 `FORMAT_DETAILS` 的 `lossy` 标记同源，见 3.4），不需要额外探测。

### 3.3 AudioSwitchService 核心逻辑

对照 PictureSwitchService 逐环节对齐：

```python
import os, shutil, subprocess, asyncio, json
from pathlib import Path
from concurrent.futures import ThreadPoolExecutor

# ---- ffmpeg / ffprobe 路径 ----
# 模块加载时只计算路径（可能为 None），不在模块顶层 raise——
# 否则 dev 环境未下载 ffmpeg 时，import 本模块会连带整个后端（含 /docs）无法启动
_BUNDLED_FFMPEG = BASE_DIR / "ffmpeg/bin/ffmpeg.exe"
_BUNDLED_FFPROBE = BASE_DIR / "ffmpeg/bin/ffprobe.exe"

FFMPEG = str(_BUNDLED_FFMPEG) if _BUNDLED_FFMPEG.exists() else shutil.which("ffmpeg")
FFPROBE = str(_BUNDLED_FFPROBE) if _BUNDLED_FFPROBE.exists() else shutil.which("ffprobe")

_AUDIO_EXECUTOR = ThreadPoolExecutor(max_workers=2, thread_name_prefix="audio-")

MAX_FILE_SIZE = 200 * 1024 * 1024
MAX_FILES = 50

# 子进程超时（秒）：ffmpeg/ffprobe 遇到畸形输入可能挂起，
# 无超时会把线程池 2 个 worker 永久占满，导致后续所有转换请求排队卡死
FFPROBE_TIMEOUT_SECONDS = 10    # 本地文件探测元数据，10 秒足够
FFMPEG_TIMEOUT_SECONDS = 300    # 200MB 音频转换，5 分钟上限


def _ensure_ffmpeg() -> None:
    """惰性依赖检查：真正要转换时才发现缺失，而不是 import 即崩溃。"""
    if not FFMPEG or not FFPROBE:
        raise ConfigurationError("ffmpeg/ffprobe 未找到，请运行 npm run download:ffmpeg")


def _probe_metadata(path: str) -> dict:
    """ffprobe 提取音频元数据（含真实编码格式）。失败时返回默认值，让 ffmpeg 继续尝试转换。"""
    try:
        result = subprocess.run(
            [FFPROBE, "-v", "quiet", "-print_format", "json",
             "-show_format", "-show_streams", path],
            capture_output=True, text=True, check=True,
            timeout=FFPROBE_TIMEOUT_SECONDS,
        )
        info = json.loads(result.stdout)
        fmt = info.get("format", {})
        stream = next((s for s in info.get("streams", []) if s["codec_type"] == "audio"), {})
        return {
            "duration": float(fmt.get("duration", 0)),
            "sample_rate": int(stream.get("sample_rate", 0)),
            "codec_name": str(stream.get("codec_name", "")),  # 真实编码，如 mp3/flac/vorbis
        }
    except (subprocess.CalledProcessError, subprocess.TimeoutExpired,
            json.JSONDecodeError, ValueError, KeyError, StopIteration):
        logger.warning("ffprobe 读取元数据失败: %s", path)
        return {"duration": 0.0, "sample_rate": 0, "codec_name": ""}


def _convert_one_sync(self, index, filename, data, params, task_dir):
    # 1. 文件大小校验（后端防御）
    if len(data) > MAX_FILE_SIZE:
        raise BadRequestError(
            f"文件过大（>{MAX_FILE_SIZE // (1024 * 1024)}MB）: {filename}"
        )

    # 2. 扩展名白名单检查
    if not is_supported_input(filename):
        raise BadRequestError(f"不支持的音频格式: {filename}")

    # 3. 写入临时输入文件（扩展名保留，便于 ffmpeg 按容器探测）
    ext = Path(filename).suffix.lower()
    input_path = task_dir / f"_in_{index}{ext}"
    input_path.write_bytes(data)

    # 4. ffprobe 读取元数据（含真实编码，供 original_format 与展示）
    metadata = _probe_metadata(str(input_path))

    # 5. original_format 以 ffprobe 识别的真实格式为准，而不是扩展名
    #    （如把 MP3 改名 .wav 上传，仍报告 mp3；识别失败时回退扩展名）
    original_format = resolve_original_format(metadata, filename)

    # 6. 输出路径：先写含 index 的唯一临时名，成功后原子 rename 到最终名。
    #    原因：ffmpeg 自行打开输出文件，无法用图片版的 "xb" 独占创建防竞态；
    #    唯一临时名保证同批次并发（2 线程）互不干扰，rename 阶段再做重名去重
    target_ext = get_target_extension(params.target_format)
    tmp_output = task_dir / f"_out_{index}{target_ext}"
    converted_name = change_extension(filename, target_ext)
    final_path = task_dir / converted_name

    # 7. ffmpeg 转换（带编码参数 + 超时）
    #    编码参数来自 AUDIO_ENCODE_ARGS（见 2.5 的策略表）
    _ensure_ffmpeg()
    args = [FFMPEG, "-y", "-i", str(input_path),
            *AUDIO_ENCODE_ARGS.get(params.target_format.lower().lstrip("."), []),
            str(tmp_output)]
    try:
        subprocess.run(
            args,
            check=True,
            stdout=subprocess.DEVNULL,
            stderr=subprocess.PIPE,
            text=True,
            timeout=FFMPEG_TIMEOUT_SECONDS,
        )
    except subprocess.CalledProcessError as e:
        input_path.unlink(missing_ok=True)
        tmp_output.unlink(missing_ok=True)
        stderr_tail = e.stderr.strip().split('\n')[-2:] if e.stderr else []
        raise BadRequestError(
            f"音频转换失败: {filename} — {'; '.join(stderr_tail)}"
        ) from e
    except subprocess.TimeoutExpired:
        # subprocess.run 超时时已 kill 子进程；清理临时文件后给用户明确错误
        input_path.unlink(missing_ok=True)
        tmp_output.unlink(missing_ok=True)
        raise BadRequestError(f"音频转换超时: {filename}")

    # 8. 原子 rename 到最终名（含重名处理：目标已存在时追加 _1, _2...）
    #    Windows 上 os.rename 目标存在时抛 FileExistsError，用异常循环替代 exists 预检
    counter = 1
    while True:
        try:
            tmp_output.rename(final_path)
            break
        except FileExistsError:
            stem = Path(filename).stem
            converted_name = f"{stem}_{counter}{target_ext}"
            final_path = task_dir / converted_name
            counter += 1

    # 9. 读取结果并清理临时输入
    converted_data = final_path.read_bytes()
    input_path.unlink(missing_ok=True)

    # 10. warning：源有损 → 目标无损时提示用户（判定依据 FORMAT_DETAILS 的 lossy 标记）
    warning = None
    if original_format in LOSSY_FORMAT_IDS and \
            params.target_format.lower().lstrip(".") in LOSSLESS_FORMAT_IDS:
        warning = "源文件为有损格式，转换为无损格式不会恢复已损失的音质"

    return {
        "index": index,
        "original_name": filename,
        "converted_name": converted_name,
        "original_format": original_format,
        "target_format": params.target_format,
        "original_size": len(data),
        "converted_size": len(converted_data),
        "size_ratio": round(len(converted_data) / len(data), 4) if data else 0.0,
        "duration_seconds": round(metadata["duration"], 1),
        "sample_rate": metadata["sample_rate"],
        "status": "success",
        "error": None,
        "warning": warning,
    }
```

关键对齐点（均对齐图片版修复后的实现）：

- `convert_stream` — 请求级校验（非空、MAX_FILES）+ `f.read()` 异常保护（读取失败该文件记 error，继续其余文件，防 task_dir 泄漏）
- `AUDIO_BATCH_SIZE = 2` 分批并发提交 — 与图片版 `PIL_BATCH_SIZE` 相同模式，批满即提交并释放内容引用，控制内存峰值
- `_error_result()` 统一把异常转为 error 条目 — 与图片版同构
- `loop.run_in_executor(_AUDIO_EXECUTOR, self._convert_one_sync, ...)` — 包装到线程池
- 文件大小校验 — 后端防御层
- `is_supported_input()` — 扩展名白名单
- Controller 层 `target_format` 白名单校验 — 非法格式直接 400（对齐图片版四枚举校验）
- `task_dir` — 任务级隔离目录
- 重名处理 — 唯一临时名 + 原子 rename + `_1, _2` 后缀去重（对齐图片版 "xb" 独占创建的并发安全思路）
- stderr 包含在异常消息中 — 用户能看到具体错误原因
- 异常分支清理临时文件 — 不残留 `_in_*` 和不完整输出
- 结果按 index 升序 — 分批并发下批次内/批次间保持提交顺序

### 3.4 AudioSwitchUtils

```python
from typing import Optional, Dict, Any, List
from pathlib import Path

# 扩展名 → MIME 类型
EXT_TO_MIME: Dict[str, str] = {
    ".wav":  "audio/wav",
    ".flac": "audio/flac",
    ".aiff": "audio/aiff",
    ".aif":  "audio/aiff",
    ".mp3":  "audio/mpeg",
    ".m4a":  "audio/mp4",
    ".aac":  "audio/aac",
    ".ogg":  "audio/ogg",
    ".opus": "audio/opus",
}

# 格式标识 → 标准扩展名（含点）
FORMAT_TO_EXT: Dict[str, str] = {
    "wav":  ".wav",
    "flac": ".flac",
    "aiff": ".aiff",
    "mp3":  ".mp3",
    "aac":  ".m4a",
    "ogg":  ".ogg",
    "opus": ".opus",
}

SUPPORTED_EXTENSIONS = set(EXT_TO_MIME.keys())

# 有损/无损格式标识集合（warning 判定用，与 FORMAT_DETAILS 的 lossy 标记一致）
LOSSY_FORMAT_IDS = {"mp3", "aac", "ogg", "opus"}
LOSSLESS_FORMAT_IDS = {"wav", "flac", "aiff"}

# 有损输出的编码参数（2.5 策略表的固化形态；AAC/OPUS 实现阶段实测后补全）
AUDIO_ENCODE_ARGS: Dict[str, List[str]] = {
    "mp3": ["-c:a", "libmp3lame", "-q:a", "0"],
    "ogg": ["-c:a", "libvorbis", "-q:a", "6"],
    "aac": ["-c:a", "aac"],  # 高质量 VBR 档位实现时按 ffmpeg 构建实测补 -q:a
    "opus": [],  # libopus 默认 VBR，实现时实测默认码率后决定是否补参数
}

# ffprobe codec_name → 格式标识（用于报告真实格式，而不是扩展名）
# WAV/AIFF 的 codec_name 是 pcm_*，需前缀匹配；识别不到时回退扩展名
CODEC_NAME_TO_ID: Dict[str, str] = {
    "mp3": "mp3",
    "flac": "flac",
    "vorbis": "ogg",
    "opus": "opus",
    "aac": "aac",
}

# 扩展名 → 格式标识归一（.m4a 是容器扩展名，格式标识是 aac；.aif 归一到 aiff）
EXT_ID_TO_FORMAT_ID: Dict[str, str] = {
    "m4a": "aac",
    "aif": "aiff",
}


def resolve_original_format(metadata: dict, filename: str) -> str:
    """以 ffprobe 识别的真实格式为准，识别失败回退扩展名。

    优先级：codec_name 精确映射 > pcm_* 前缀（wav/aiff 按扩展名区分）> 扩展名（含归一）。
    """
    codec = str(metadata.get("codec_name", ""))
    if codec in CODEC_NAME_TO_ID:
        return CODEC_NAME_TO_ID[codec]
    ext_id = Path(filename).suffix.lower().lstrip(".")
    if codec.startswith("pcm_"):  # WAV/AIFF 的 PCM 编码，按扩展名区分
        return "wav" if ext_id == "wav" else "aiff"
    return EXT_ID_TO_FORMAT_ID.get(ext_id, ext_id)


def is_supported_input(filename: str) -> bool:
    return Path(filename).suffix.lower() in SUPPORTED_EXTENSIONS


def get_target_extension(target_format: str) -> str:
    fmt = target_format.lower().lstrip(".")
    return FORMAT_TO_EXT.get(fmt, f".{fmt}")


def change_extension(filename: str, new_ext: str) -> str:
    return f"{Path(filename).stem}{new_ext}"
```

对比 PictureUtils（~500 行），AudioUtils 约 100 行。没有魔数检测、没有缩放计算、没有色彩模式；保存参数只有一张 6 项的编码策略表（`AUDIO_ENCODE_ARGS`）。

### 3.5 AudioSwitchTaskStore

独立但结构相同。`StoredFile` 移除 `converted_resolution`：

```python
@dataclass
class StoredFile:
    path: Path
    converted_name: str
    converted_size: int
```

任务生命周期与 PictureTaskStore **修复后的实现**一致，必须完整沿用以下机制（不得回退到修复前版本）：

- `register_async` — 异步注册，LRU 目录删除与 zip 打包放线程池，不阻塞事件循环
- `_write_zip` — 静态方法，供线程池调用
- `get_filename` — 同时校验上下界（`0 <= index < len`），拒绝负索引
- `OUTPUT_DIR / task_id` 隔离、`TASK_CLEANUP_SECONDS` 到期清理、`MAX_TASKS` LRU 淘汰

三个状态对应的 UI：

## 五、构建与打包

### 5.1 需要打包的二进制

ffmpeg 发行版包含 3 个 exe：

| 文件        | 大小  | 用途                      | 是否打包  |
| ----------- | ----- | ------------------------- | --------- |
| ffmpeg.exe  | ~97MB | 音频编码/转码             | ✅ 打包   |
| ffprobe.exe | ~97MB | 读取元数据（时长/采样率） | ✅ 打包   |
| ffplay.exe  | ~99MB | 音频播放（命令行）        | ❌ 不打包 |

上次说要只打包 ffmpeg.exe，但深入分析后 ffprobe 是用来获取时长的，必须打包。两文件合计 ~194MB。

分发合规注意：ffmpeg 构建分 LGPL 与 GPL 两种。本模块只编码 mp3/vorbis/opus/aac，不含 x264 等 GPL 组件，优先选用 LGPL 构建（如 gyan.dev 的 ffmpeg-release-essentials 版已含上述编码器），避免 GPL 分发义务；若实际下载源只能提供 GPL 构建，需在应用内提供源码获取渠道。

打包命令：

```
--add-data "ffmpeg/bin/ffmpeg.exe;ffmpeg/bin"
--add-data "ffmpeg/bin/ffprobe.exe;ffmpeg/bin"
```

.spec datas 同理追加两条。

### 5.2 ffmpeg 可用性检查

不在模块顶层检查（见 3.3 的 `_ensure_ffmpeg` 设计）：dev 环境未下载 ffmpeg 时，后端仍能启动并访问 /docs。检查分两层：

1. 启动检查（lifespan 内，对齐图片版模式）：探测两文件，缺失时记录 error 日志 + `app.state` 标记，不阻断启动；
2. 调用检查（转换接口首次转换时 `_ensure_ffmpeg()`）：缺失时抛 `ConfigurationError`，接口返回 500 并提示"请运行 npm run download:ffmpeg"。

理由是 `npm run download:ffmpeg` 下载的是完整包，两个文件天然存在——如果其中一个不存在说明下载不完整或用户手动删了，应该明确报错。
