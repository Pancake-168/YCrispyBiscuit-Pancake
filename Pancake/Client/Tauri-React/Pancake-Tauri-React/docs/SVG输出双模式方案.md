# SVG 输出双模式方案

> 编写日期：2026-07-14
> 目标：为图片转换功能新增 SVG 专属输出模式，让本地用户手动区分“快速导出 SVG 容器”和“真实矢量化描摹”两种场景。

---

## 一、问题背景

当前系统里，只要目标格式是 SVG，后端就统一走矢量化分支。

这会带来两个实际问题：

1. PNG/JPG 等位图转 SVG 时，不存在“普通转码”，当前实现实际做的是位图矢量化，耗时和结果都高度依赖图片复杂度。
2. 用户在“只是想要一个 SVG 文件容器”和“想要真实可缩放的矢量路径”之间没有选择权，导致照片、截图、复杂插画也会误走重计算路径。

因此需要把 SVG 输出从“单一路径”改成“双模式路径”。

---

## 二、方案结论

新增一个仅在目标格式为 SVG 时显示的字段：`svg_mode`。

建议值：

1. `embed`：位图封装
2. `vectorize`：矢量化描摹

默认值建议为 `embed`，因为它更快、更稳定、更适合本地工具的常规使用场景。

---

## 三、两种模式的语义

### 3.1 `embed` 位图封装

含义：输出文件后缀是 `.svg`，但 SVG 内部放的是位图内容，而不是大量 `path`。

特点：

1. 处理速度快，接近普通位图转码。
2. 对照片、截图、复杂插画稳定，不容易长时间卡住。
3. 输出文件虽然是 SVG，但本质不是可编辑的真实矢量图。
4. 放大时是否清晰，仍取决于内部位图分辨率。

适用场景：

1. 只是需要 `.svg` 文件容器。
2. 想避免 JPG/PNG 转 SVG 时长时间等待。
3. 图片内容本身不适合矢量化。

### 3.2 `vectorize` 矢量化描摹

含义：沿用当前 SVG 输出逻辑，对位图颜色区域和轮廓进行分析，生成真正的 SVG 路径。

特点：

1. 输出结果是矢量路径，可无限缩放。
2. 计算明显更重，耗时受分辨率、颜色数、边缘复杂度影响很大。
3. 对 icon、logo、线稿、少色块图形更合适。
4. 对照片、截图、渐变插画往往又慢又不好看。

适用场景：

1. 图标、Logo、单色或少色图形。
2. 需要真实矢量路径，而不是 SVG 容器。

---

## 四、前端改动方案

位置：图片转换页目标格式选择区域。

交互规则：

1. 仅当 `targetFormat === 'svg'` 时显示 `SVG 输出模式` 选项。
2. 选项文案不要写“普通转码”，应写成“位图封装”和“矢量化描摹”，避免误导。
3. 默认选中 `位图封装`。
4. 选中 `矢量化描摹` 时显示警告提示：仅适合 Logo、icon、线稿、少色图，不适合照片和截图。
5. 选中 `位图封装` 时隐藏矢量化相关提示，避免让用户误以为输出一定是矢量图。

前端请求参数新增：

1. 字段名：`svg_mode`
2. 发送条件：仅当目标格式为 `svg` 时发送
3. 默认值：`embed`

---

## 五、后端改动方案

后端 `convert` 接口新增一个表单字段：`svg_mode`。

建议取值：

1. `embed`
2. `vectorize`

后端分支规则：

1. 当 `target_format != 'svg'` 时，忽略 `svg_mode`。
2. 当 `target_format == 'svg'` 且 `svg_mode == 'embed'` 时，生成“内嵌位图的 SVG”。
3. 当 `target_format == 'svg'` 且 `svg_mode == 'vectorize'` 时，走现有 `_save_as_svg` 矢量化路径。

建议同时补 2 个防护：

1. `vectorize` 模式下增加尺寸或总像素限制，避免再出现长时间无响应。
2. `vectorize` 模式下增加更明确的错误信息，例如“图片过大或过于复杂，不适合矢量化描摹”。

---

## 六、推荐实现方式

`embed` 模式建议输出标准 SVG 文本，内部使用 `<image>` 承载位图数据。

建议做法：

1. 先把输入图按现有缩放、色彩模式、透明填充逻辑处理完。
2. 再将处理后的位图编码成 PNG 或 JPEG 字节。
3. 以 base64 Data URL 的形式内嵌到 SVG 的 `<image>` 节点中。
4. `viewBox`、`width`、`height` 直接使用处理后图片尺寸。

原因：

1. 不依赖额外文件路径，单个 SVG 文件即可独立使用。
2. 对本地工具最省事，导出和下载行为与当前体系兼容。
3. 实现难度低，不需要引入新的外部服务或重构整体转换链路。

---

## 七、默认策略建议

默认行为建议如下：

1. SVG 默认输出模式为 `embed`。
2. `vectorize` 作为高级选项保留给明确知道自己在做什么的用户。
3. 文档、提示语、页面文案统一明确：`embed` 不是矢量图，只是 SVG 容器；`vectorize` 才是真正矢量化。

这个方案的核心收益，不是“让 SVG 更强”，而是把两类完全不同的需求拆开，避免用户把重型矢量化误当成普通格式转换。
